# 現場報告腳本（4–7 分鐘，學生評審）

策略：**少講、多切換、讓對比說話**。全程在遊戲畫面上操作，投影片最多 2–3 張
（開場定位、技術名詞對照、QR code）。一人講、一人操作，事先排練到「話講到哪、
畫面切到哪」。

## 流程

### 0:00–0:30 開場 — 直接停在遊戲畫面上，不要從標題投影片開始

畫面停在**夕陽＋下雨＋水面漣漪**的場景（最美的一幀）。一句話定位：

> 「我們做了一個像素風 3D 養成遊戲，整個畫風是用渲染管線即時做出來的，不是貼圖畫的。」

### 0:30–2:30 「魔術拆解」— 技術含金量的主秀

在大螢幕上現場逐一關掉效果再開回來，每切一次配一句 CG 課術語：

| 操作 | 畫面變化 | 講的術語 |
| --- | --- | --- |
| 關描邊 → 開回來 | 整個畫面糊掉 | depth/normal **edge detection**（multi render target 多輸出 depth + view-normal） |
| 關 cel shading | 變回普通 3D | **toon ramp**（連續光照量化成四階） |
| 解析度 540p → 原生 | 像素感消失 | 低解析度離屏渲染 + **nearest-neighbour upscale** |

這段同時滿足「好看」和「不偏題」——評審親眼看到每個效果各自的貢獻，
比任何投影片都有說服力。

### 2:30–4:00 生命感段落

- 拉**時間滑桿**從日出掃到月夜（影子跟著太陽轉、夜晚水面變月色）。
- 按 **Water** 召喚一場雨：雨絲、池塘漣漪、地面 splash ring。
- 切到 **Growth 模式**看 30 天生長 morph（或在 Game 模式按 `F` / Settings →
  Demo → Skip to Day 30 直接快轉滿樹）。

講的術語：**procedural tree generation**（整棵樹是參數生出來的，一個生長值連續變形）、
**morph target**（Morph 模式：每個頂點在幼苗與成樹之間插值）。

### 4:00–結尾 全場互動

投影片放 **QR code**，讓所有評審當場用手機打開遊戲自己玩、自己澆水養樹、
戳水面起漣漪、戳樹掉葉子。報告結束後他們手機裡還開著作品——打分的時候
印象分直接拉滿。

## 現場互動可以順手秀的（已實作）

- 拖曳 → 轉視角（pixel-perfect camera，轉動時像素不抖）
- 點水面 → 漣漪從點擊處擴散
- 點樹 → 樹搖晃、樹冠灑落葉（幼苗期不掉葉）
- `F` 鍵 / Settings → Demo → ⏩ Skip to Day 30

## 報告前還要準備的

- [ ] **部署公開網址 + QR code**（`npm run build` → GitHub Pages / Vercel；現場
      Wi-Fi 不可靠，不要依賴區網 `--host`）
- [ ] 「魔術拆解」目前要開 Settings 面板切換；若要更順，可加報告用熱鍵
      （一鍵 before/after、depth/normal buffer 直接顯示）
- [ ] **備用影片**：完整跑一次流程的螢幕錄影放在桌面，現場當機直接播
- [ ] 接音響（環境音樂、雨聲是別組沒有的維度）、瀏覽器全螢幕、關通知
- [ ] 計時排練至少兩次；超時砍的順序：先砍日夜滑桿展示，再砍 normal buffer，
      **開場、拆解、互動、QR 四個點不能砍**

## 收尾話術（可替換成自己真實踩過的坑，越具體越好）

> 「像素風看起來簡單，但要讓它『動起來還是像素風』——鏡頭平移不抖、
> 輪廓線維持一個像素寬——反而是最花時間的部分。」
